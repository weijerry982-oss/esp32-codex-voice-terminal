# 测试计划

测试按 `docs/progress.md` 的阶段顺序进行，每阶段验收通过后再进入下一阶段。测试产物、记录和脚本均放在本项目目录。

- 阶段 1：Arduino IDE/固件编译、烧录和串口输出；记录板型与参数。
- 阶段 2：Wi-Fi 连接、OLED 显示、按键输入与状态 LED 分项验证；确认按钮只确认当前明确展示的任务。
- 阶段 3：麦克风 I²S 录音独立验证。
- 阶段 4：MAX98357A 扬声器播放独立验证。
- 阶段 5：Python 服务与设备局域网通信、请求来源校验及异常处理。
- 阶段 6：语音识别和语音合成链路验证。
- 阶段 7：Codex CLI 调度和确认流程验证；确认原生审批机制仍启用。
- 阶段 8：端到端联调及断网、重连、服务异常等故障恢复。

每次记录测试前提、操作步骤、预期结果、实际结果和未解决问题。不得把未在真实硬件完成的测试描述为硬件通过。

## 阶段 8 整机联调与恢复测试（2026-10-18）

1. 正常端到端：语音 → ChatGPT 输入框草稿 → GPIO39 发送 → ChatGPT 回答 → TTS/OLED 播放。已完成 task `529388`、`604133`。
2. 草稿过期：创建草稿后不按任何键，55 秒后设备自动调用 cancel，ChatGPT 输入框清空，OLED 显示 EXPIRED。已通过 task `339638`。
3. Python 服务不可用：停止服务后发起语音请求，设备应报错但继续运行；重启服务后新任务应恢复。已通过：`Task request HTTP -1` 两次；恢复后 task `604654` 完成。
4. ChatGPT 应用关闭：关闭 ChatGPT 后发起请求，服务应返回不可用/设备报错；重新打开后新任务应恢复。已通过：修复前服务断开连接（HTTP 000），修复后返回 503 `chatgpt_unavailable`；重开应用约 15 秒后 task `346995` 创建成功并取消。
5. Wi-Fi 断网/恢复：断开 AP 约 20 秒，设备应有界重试；恢复 AP 后重新连接，端到端任务应恢复。已实现并烧录 OLED 状态（`WIFI CONNECT`/`WIFI OK`/`WIFI LOST`，显示 SSID 和 IP）；待断开 AP 目视验证。
6. 长时间运行：设备与服务连续运行，观察是否复位、卡死或未释放任务。待最终联调后执行。

补充：ChatGPT 回答屏显示后保留 10 秒再回待机；若 TTS 播放超过 10 秒，则在播放结束后回待机。已实现并烧录，待端到端目视验证。

7. 长回答音频：task `893283` 的 TTS WAV 为 3,166,446 字节，超过旧 2 MB 缓冲区，设备未播放；回答缓冲已调整为 6 MB（5/4/2 MB 回退）并烧录，待重问验证。
8. 按钮中文状态：GPIO0 按住“正在录音 + 剩余秒数（20→0）”、松开“正在上传”；GPIO39 “正在发送”；GPIO40 “正在取消发送”。已烧录，待目视验证。
9. 确认前摘要：待确认页交替显示任务 ID + 转录摘要和按键提示；摘要不可用时 GPIO39 不能发送；提示页第一次按 GPIO39 只切换到摘要，第二次才发送。已烧录，待目视验证。
10. 安全核对：当前为明文 HTTP + 来源 IP 允许列表，无 TLS/设备令牌/HMAC；仅限受信局域网，已记录在协议文档。
11. 空闲熄屏：IDLE 60 秒后 OLED 熄屏，RGB 绿色 1 秒亮/1 秒灭；按键/Wi-Fi/任务事件唤醒。息屏后第一次按键只唤醒，不执行按键动作；GPIO0 再次按住才录音。串口已捕获到 `Display: idle sleep; green LED blinks every 1 s.`，OLED 和 LED 的实际视觉效果待目视确认。
