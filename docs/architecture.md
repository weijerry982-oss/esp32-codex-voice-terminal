# 系统架构

## 组件职责

- **ESP32-S3 语音终端**：管理 Wi-Fi、OLED、按键和状态灯；采集麦克风音频、播放收到的音频，并通过局域网与电脑服务通信。实体确认只对应 OLED/界面明确展示的当前待确认任务。
- **Windows Python 服务**：作为可信局域网中的设备接入与任务协调层，校验请求来源和数据，提供设备状态/任务交互，并按明确的安全边界协调 Codex CLI。服务默认仅监听本机或可信局域网。
- **Codex CLI**：执行其自身支持的编码任务和权限流程。服务与硬件不得绕过、关闭或替代 Codex CLI 的审批机制，不得将未经验证的语音直接变成任意 Windows 命令。

## 通信关系

ESP32 通过 Wi-Fi 与 Python 服务交换状态、控制请求及音频相关数据；Python 服务负责来源校验、任务状态维护和安全交互；Codex CLI 由电脑端服务侧按其原生方式调用/协作。具体传输协议、消息格式、鉴权和超时策略留待 `docs/protocol.md` 后续定义，并在阶段 5 设计验证。

## 边界与阶段

先完成固件基础和外设验证，再实现网络服务及语音/任务流程。GPIO 以 `docs/hardware.md` 最终确认的表格为准。未通过当前阶段验收不得进入下一阶段。
